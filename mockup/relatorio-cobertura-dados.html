Gaps Criticos — Dados Faltantes

1. Owner de propriedade no Reservas

A tabela properties do Reservas NAO tem owner_id. Impossivel vincular checkout de hospede ao proprietario do imovel.

Afeta: Pesquisa satisfacao pos-checkout (SZS Quente) e Hospede->SZS Morno (cross)

Solucao: Cruzar via Sapron account_owner.properties_owned + property_property. Ou buscar o link no Pipedrive (deal SZI Won contem person_id do proprietario + empreendimento).

2. Metricas de email (abertura/clique)

Nenhum MCP tem dados de abertura ou clique de email. Impossivel implementar triggers comportamentais.

Afeta: Trigger comportamental SZI e Trigger comportamental MKP (2 comunicacoes)

Solucao: Implementar via SIA (Resend tem webhooks de open/click) ou integrar RD Station se for adotado. Precisa de pipeline de eventos.

3. Interacoes MIA/Blip

Conversas do chatbot (MIA/Morada via Blip) nao estao no data lake Nekt. Nao e possivel segmentar por comportamento no bot.

Afeta: Nenhuma comunicacao diretamente, mas limita refinamento futuro de temperatura

Solucao: Nao bloqueia MVP. Considerar ingestao futura via API Blip/Morada.

4. Template MKP Repescagem no Meta

SZI tem 9 templates de repescagem aprovados. MKP tem ZERO. Precisam ser criados e aprovados no Meta antes de implementar.

Afeta: Repescagem MKP por empreendimento

Solucao: Roberto criar templates no Morada/Meta. Processo leva ~48h de aprovacao.

Alertas Operacionais

Telefone/email via JOIN obrigatorio: deals_kpi_base nao tem contato. Toda query de disparo precisa fazer JOIN com pipedrive_persons_expanded (169K, 100% email+phone) via person_id das activities ou pipedrive_deals_readable.
Activities em Bronze: A tabela de atividades esta em nekt_operacional_bronze (nao silver). Dados nao curados — pode haver duplicatas ou inconsistencias. 92K de 112K reunioes tem deal_id linkado.
Nomenclatura MKT vs MKP: Nos dados Pipedrive a vertical aparece como "MKT", nao "MKP". Confirmar com Roberto qual e o correto antes de implementar.
Colunas de data no Reservas: Sao check_in_date e check_out_date (tipo date), nao check_in/check_out. Spec deve usar os nomes corretos.
